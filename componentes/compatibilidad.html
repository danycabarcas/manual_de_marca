Compatibilidad con Tailwind, Prime y otras librerías

Cómo conviven los componentes gob-* con Tailwind, PrimeNG/PrimeVue, Angular Material, Bootstrap y MUI; qué prima y recetas.

Respuesta corta: conviven sin chocar. Un control con clase (de Prime, Tailwind, Material o suya) siempre prima sobre gob; gob solo viste lo que no tiene clase, y sus componentes gob-* están aislados en Shadow DOM.

01. Cómo está construido para no chocar

  1. Componentes gob-*: Shadow DOM. Ni el CSS de Tailwind/Prime/Bootstrap entra, ni el de gob sale. Lo único que atraviesa son variables (--gob-*) y la tipografía heredada.
  2. gob.css: todas las clases llevan prefijo mg- y todas las variables --mg-/--gob-. Los efectos globales (tipografía, fondo, encabezados, foco) son opcionales (.mg-base o .mg-forms) y de especificidad cero: cualquier regla suya las supera.
  3. Controles HTML nativos: los que no tienen clase se estilizan con especificidad normal (vencen al «preflight» de Tailwind); los que sí tienen clase solo reciben reglas de especificidad cero, y los de librerías (p-*, mat-*, mdc-*, form-*, btn*, ant-*, Mui*, v-*, el-*) quedan excluidos. class="mg-nativo-off" excluye uno a mano.

02. Matriz de compatibilidad

Con…ResultadoQué hacer
Tailwind CSS v3Probado Las utilidades (text-sm, border-4, rounded-none, bg-red-600) ganan a gob en cualquier elemento con clase. Los controles sin clase siguen con la marca (incluso con el «preflight»).Cargue gob.css en cualquier orden.
Tailwind CSS v4Probado Con gob.layer.css cargado antes de Tailwind: las utilidades ganan y los controles sin clase conservan la marca. Con gob.css (sin capa) el CSS sin capa le gana a las utilidades de v4.Use gob.layer.css y póngalo primero (receta abajo).
PrimeNG / PrimeVue / PrimeReactProbado (PrimeVue 4.5.5 + Aura) Los p-* se ven idénticos con y sin gob.css (radio, relleno, colores, alto). gob solo estiliza los controles HTML sin clase.Use p-* donde Prime tenga el componente y gob-* para lo que no tiene (tabla de decisión abajo).
Angular MaterialPor diseño Sus componentes llevan clases mat-*/mdc-* (excluidas de la capa nativa) y su CSS está encapsulado. Los gob-* viven en Shadow DOM. No se pisan. No lo hemos probado todavía en una aplicación Angular real.No ponga class="mg-base" en <body> si usa la tipografía de Material; use .mg-forms solo en las zonas con HTML nativo.
Bootstrap 4/5, AdminLTEPor diseño Sus controles llevan form-control, btn, … (excluidos). Los gob-* no heredan su CSS.Preferible usar el tema de este repositorio (magdalena-bootstrap5.css) para los componentes de Bootstrap.
MUI, Vuetify, Ant Design, ElementPor diseño Excluidos por prefijo de clase (Mui*, v-*, ant-*, el-*).Igual que Prime: su componente donde exista, gob-* para el resto.
Temas de WordPress / CSS propioPor diseño Todo en gob.css lleva prefijo mg-/--mg-/--gob-. Los efectos globales son opcionales (.mg-base, .mg-forms) y de especificidad cero.Si choca el tipo de letra o el fondo, no use mg-base: use mg-forms o solo los gob-*.

«Probado» = verificado en el navegador con la librería real (Tailwind 3.4 y 4.1, PrimeVue 4.5.5). «Por diseño» = se deduce de las exclusiones y el encapsulamiento, sin prueba en una app real.

Regla: no duplique el mismo tipo de componente en una pantalla. Prime donde Prime tenga el suyo; gob para lo que no tiene. Ambos usan los mismos colores si aplica el preset magdalena-preset. Detalle de licencias y versiones en Estándar y licencias.

05. Recetas

Tailwind v4
/* Tailwind v4 — en su CSS principal (el orden de los @import importa) */
@import url('https://manualdemarca.magdalena.gov.co/cdn/v1/gob.layer.min.css');   /* declara: theme, base, gob, primeng, components, utilities */
@import 'tailwindcss';

/* o en HTML: gob.layer.css ANTES de su hoja de Tailwind */
/* <link rel="stylesheet" href=".../cdn/v1/gob.layer.css"> <link rel="stylesheet" href="/css/app.css"> */
PrimeNG / PrimeVue
// PrimeNG 18–21 (app.config.ts): ponga a Prime en una capa para que el orden sea explícito
providePrimeNG({ theme: { preset: MagdalenaPreset, options: { cssLayer: { name: 'primeng', order: 'theme, base, gob, primeng, components, utilities' } } } });
// y cargue gob.layer.css (que ya declara ese mismo orden) en styles / index.html.

// PrimeVue 4:  app.use(PrimeVue, { theme: { preset: MagdalenaPreset, options: { cssLayer: { name: 'primeng', order: 'theme, base, gob, primeng, components, utilities' } } } });
  • Capas CSS: gob.layer.css es el mismo contenido en @layer gob (orden theme, base, gob, primeng, components, utilities): queda por encima del preflight y por debajo de las utilidades y de Prime. Si lo carga después de Tailwind v4 el orden ya está fijado: cárguelo siempre primero.
  • Capas de z-index: los menús, selectores y calendarios de gob flotan en z-index: 1000; los overlays de Prime usan su propio z-index base (también ~1000). Si una pantalla mezcla ambos y se solapan, ajuste el zIndex de Prime en su configuración (las ventanas modales de gob usan la capa superior del navegador y no se solapan).

06. Qué sí puede chocar

  • Dos hojas que fijan la tipografía/fondo de body (use .mg-forms en vez de .mg-base).
  • gob.css sin capa + Tailwind v4 (use gob.layer.css).
  • Dos componentes del mismo tipo en la misma pantalla (elija uno).
  • Un CSS global agresivo del proyecto que apunte a * con !important: no entra al Shadow DOM, pero sí afecta a lo nativo.
