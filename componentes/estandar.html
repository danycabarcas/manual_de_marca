Estándar de componentes

Una sola fuente de tokens, presets para PrimeNG y otras librerías, y Web Components gob-* para lo que ellas no cubren. Guía de decisión, contrato y licencias.

Cómo se mantienen estándar los componentes cuando los proyectos usan PrimeNG, Material, MUI u otros: una sola fuente de tokens, el mismo preset generado para cada librería y una familia de Web Components gob-* solo para lo que esas librerías no cubren.

01. Un origen, muchas salidas

Tokenstools/tokens.py
colores · tipografía · radios · sombras
→
CSS --mg-* / --gob-*Tailwind v3 / v4PrimeNG · PrimeVue (preset)Angular Material (M2/M3)MUI · VuetifyBootstrap · AdminLTEWeb Components gob-*

Cambiar un color o un radio en tools/tokens.py actualiza, con un solo comando, el CSS, Tailwind, los temas de PrimeNG/PrimeVue, Material, MUI y Vuetify, y los Web Components. Así «el azul institucional» es el mismo en todos los proyectos.

03. Evidencia: PrimeVue con el preset

El mismo preset (dist/primeng/magdalena-preset.mjs) aplicado a componentes reales de PrimeVue 4.5.5: botones, formularios, tabla, etiquetas y mensajes toman la marca, incluidos los colores de estado. Un componente mg-* (abajo a la izquierda) convive sin conflicto. El preset es el mismo para PrimeNG (el import cambia según la versión; ver cabecera del archivo).

05. Contrato de un componente gob-*

Lista de verificación que debe cumplir todo componente nuevo antes de entrar a la librería.

  1. Nombre: etiqueta gob-<nombre> en español, singular (gob-mapa-magdalena, gob-grafica).
  2. API: propiedades en camelCase con atributo en kebab-case; los datos complejos entran por propiedad (JSON), nunca por HTML. Todo configurable con el.config = {…}.
  3. Eventos: gob-<nombre>-<acción>, bubbles + composed, con detail documentado (el código DIVIPOLA es siempre la llave, nunca el nombre).
  4. Tema: variables --gob-<componente>-* con valores por defecto de la marca, ::part() para lo estructural, tema claro/oscuro y sin colores escritos a mano.
  5. Accesibilidad (WCAG 2.1 AA / NTC 5854): teclado completo, roles ARIA, foco visible, alternativa en texto para lo gráfico, contraste ≥ 4.5:1, prefers-reduced-motion.
  6. Responsive e imprimible: de 320 px a 4K (container queries), CSS de impresión.
  7. Peso: bundle base < 50 KB gzip; librerías pesadas (ECharts, MapLibre) se cargan solo bajo demanda.
  8. Documentación: cuándo usar / cuándo no, demo en vivo, instalación (CDN, Angular, React/Next, Vue), propiedades, eventos, variables, accesibilidad e integración con la API NestJS.
  9. Calidad: axe-core sin violaciones, versionado semántico y ruta inmutable por versión mayor (/cdn/v1/).

06. Licencias de las librerías de componentes

Atención con las versiones más recientes

PrimeNG 22 y PrimeVue 5 cambiaron a la PrimeUI License: exige clave de licencia y la modalidad gratuita aplica a organizaciones pequeñas (menos de 10 empleados y 5 desarrolladores, entre otros límites). Una entidad pública debería presupuestar la licencia comercial por desarrollador o mantenerse en las versiones MIT. Verificado en el LICENSE.md de cada paquete; confirme los términos vigentes en primeui.dev/licenses.
